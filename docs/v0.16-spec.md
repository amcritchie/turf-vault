# TurfVault v0.16 — Specification

**Status**: Draft (spec only — no source changes yet).
**Author**: Jasper (with Alex).
**Date**: 2026-05-27.
**Target deploy**: First mainnet deploy.

## 1. Why v0.16

v0.15.1 ships a custodial-balance model: every user has a `UserAccount.balance` field, USDC sits pooled in `vault_usdc`, and Rails moves money through `deposit` / `withdraw`. The model works but pays for it in binary size — `deposit`, `withdraw`, `enter_contest` (managed), `enter_contest_with_token` (managed), the `daily_withdrawn` circuit breaker, and the dual-mint USDC+USDT plumbing collectively account for roughly 60 KB of `.text` and ~0.4 SOL of permanent ProgramData rent (see `/Users/alex/projects/turf-vault-deploy-cost.html`).

v0.16 drops the pooled-balance model for **server-signed self-custody** (the Privy / Magic.link pattern, home-grown):

- Every user has a Solana keypair. Rails holds the encrypted private key for web2 users; web3 users use Phantom.
- USDC lives in each user's **ATA** — not a vault PDA.
- Contest entry = an SPL transfer from user ATA → per-currency operator-revenue ATA.
- Contest payouts = an SPL transfer from a per-contest USDC prize-pool PDA → winner's ATA.
- No `deposit`. No `withdraw`. No `balance`. No `total_deposited` / `total_withdrawn`. No daily cap.

Mainnet has not been deployed yet, so v0.16 is the **first mainnet deploy**. Devnet state is torn down (every PDA from v0.15.1 fails the new discriminator/layout check after upgrade — that is acceptable because no real user data exists yet).

### 1.1 Goals

1. Smaller binary → cheaper permanent rent.
2. Pluggable currency registry — add USDT / EURC / a new stablecoin without redeploying.
3. Per-currency entry-fee schedule per contest (a contest can be $5 USDC or $5 USDT or both).
4. On-chain stat counters (`entries`, `wins`, `cashes`, `total_won`) so Rails can display a profile without a side database for the basics.
5. Explicit `Locked` → `Cancelled` lifecycle states; explicit cancel-and-refund-creator path.
6. Operator-revenue sweep on-chain (no more "all entry fees pool with prizes").

### 1.2 Non-goals

- Multi-asset payouts. Payouts remain **USDC-only**; the payout mint is pinned at `initialize`.
- On-chain username uniqueness / registry (deferred — Rails still owns uniqueness).
- On-chain leaderboards / scoring (still off-chain, Rails computes results).
- Refunding entrants when a contest is cancelled — operator handles off-chain via `mint_entry_token` goodwill credits (see §11 Q1).

## 3. The 15-instruction surface

v0.15.1 has 16 instruction handlers (after `force_close_vault` + `update_signers` were dropped). v0.16 has **15 plus pause/unpause** = 17 total. The diff from v0.15.1:

| Status | Instruction | Notes |
|---|---|---|
| KEEP | `initialize` | Heavy refactor — accepts `accepted_currencies` |
| KEEP | `create_user_account` | Layout changes; same validation |
| KEEP | `set_username` | Unchanged |
| KEEP | `create_season` | Unchanged |
| KEEP | `create_contest` | Heavy refactor — per-currency fee schedule, USDC prize pool |
| KEEP | `settle_contest` | Refactor — pays from contest-scoped USDC PDA to user ATA |
| KEEP | `close_contest` | Unchanged (closes a settled contest's PDA, reclaims rent) |
| KEEP | `mint_entry_token` | Unchanged |
| KEEP | `pause` / `unpause` | Unchanged |
| NEW | `register_currency` | Add a currency to `accepted_currencies` |

| NEW | `lock_contest` | Open → Locked |

| DROP | `update_signers` | Already dropped in v0.15.1 mainnet build |

### 3.1 `initialize`

**Purpose**: One-time setup. Creates the singleton VaultState PDA, pins the payout mint to USDC, registers an initial set of accepted currencies (USDC + USDT at indices 0 and 1), and locks in the multisig signer set + threshold.

**Auth**: `INIT_AUTHORITY` (Alex Phantom key, mainnet build). Dev/devnet builds skip this check.

```rust
#[derive(Accounts)]
pub struct Initialize<'info> {
    #[account(mut)]
    pub admin: Signer<'info>,

    #[account(
        init,
        payer = admin,
        space = 8 + VaultState::INIT_SPACE,
        seeds = [b"vault"],
        bump,
    )]
    pub vault_state: Account<'info, VaultState>,

    /// Payout mint — pinned to canonical Circle USDC at mainnet build time.
    pub payout_mint: Account<'info, Mint>,

    /// Second accepted entry-fee currency (USDT). Optional in dev builds;
    /// required in mainnet for parity with v0.15.1.
    pub second_currency_mint: Account<'info, Mint>,

    /// Operator-revenue ATA for the payout currency (USDC).
    /// Authority = vault_state PDA.
    #[account(
        init,
        payer = admin,
        token::mint = payout_mint,
        token::authority = vault_state,
        seeds = [b"op_rev", payout_mint.key().as_ref()],
        bump,
    )]
    pub payout_op_rev_ata: Account<'info, TokenAccount>,

    /// Operator-revenue ATA for the second currency (USDT).
    #[account(
        init,
        payer = admin,
        token::mint = second_currency_mint,
        token::authority = vault_state,
        seeds = [b"op_rev", second_currency_mint.key().as_ref()],
        bump,
    )]
    pub second_op_rev_ata: Account<'info, TokenAccount>,

    pub token_program: Program<'info, Token>,
    pub system_program: Program<'info, System>,
    pub rent: Sysvar<'info, Rent>,
}
```

**Handler signature**:
```rust
pub fn handle_initialize(
    ctx: Context<Initialize>,
    signers: [Pubkey; 3],
    threshold: u8,
) -> Result<()>
```

**Validation**:
1. `#[cfg(mainnet)]` admin == INIT_AUTHORITY
2. `#[cfg(mainnet)]` payout_mint == EXPECTED_PAYOUT_MINT (canonical Circle USDC)
3. `1 <= threshold <= 3`
4. No duplicate signers in `signers[3]`
5. `signers.contains(admin.key())` — the init authority must be a signer
6. `payout_mint.key() != second_currency_mint.key()` (sanity)

**Side effects**:
- Initialize VaultState fields including `accepted_currencies[0]` (payout/USDC) and `accepted_currencies[1]` (USDT).
- `paused = false`.

**CU estimate**: ~25,000 (two ATA inits + one PDA init).

**Errors**: `Unauthorized`, `InvalidMint`, `InvalidThreshold`, `DuplicateSigner`.

### 3.2 `register_currency`

**Purpose**: Add a currency to `accepted_currencies`. Creates the per-currency operator-revenue ATA. Idempotent rejection: if `mint` already exists in the array (active or deactivated), reject.

**Auth**: 2-of-3 multisig.

```rust
#[derive(Accounts)]
pub struct RegisterCurrency<'info> {
    #[account(mut)]
    pub admin: Signer<'info>,
    pub cosigner: Signer<'info>,

    #[account(
        mut,
        seeds = [b"vault"],
        bump = vault_state.bump,
        constraint = vault_state.validate_multisig(&admin.key(), &cosigner.key()) @ VaultError::Unauthorized,
    )]
    pub vault_state: Account<'info, VaultState>,

    pub mint: Account<'info, Mint>,

    /// Per-currency operator-revenue ATA.
    #[account(
        init,
        payer = admin,
        token::mint = mint,
        token::authority = vault_state,
        seeds = [b"op_rev", mint.key().as_ref()],
        bump,
    )]
    pub op_rev_ata: Account<'info, TokenAccount>,

    pub token_program: Program<'info, Token>,
    pub system_program: Program<'info, System>,
    pub rent: Sysvar<'info, Rent>,
}
```

**Handler signature**:
```rust
pub fn handle_register_currency(
    ctx: Context<RegisterCurrency>,
    kind: u8,
) -> Result<()>
```

`kind` is an operator tag for the currency (e.g. `0 = stablecoin`, `1 = sol-wrapped`, `2 = governance`) — informational only, never consulted by the program. Defaulting to 0 is fine.

**Validation**:
1. multisig check (constraint above)
2. find first inactive slot in `accepted_currencies`; require `slot < MAX_CURRENCIES`
3. for each existing slot `i < MAX_CURRENCIES`: require `accepted_currencies[i].mint != mint.key()` (cannot re-add a mint, even if deactivated — this preserves currency_idx stability)

**Side effects**:
- Write `accepted_currencies[slot]` with `{ mint, op_rev_ata, kind, active: true, _pad: [0; 6] }`.

**CU estimate**: ~12,000.

**Errors**: `Unauthorized`, `CurrencyAlreadyRegistered` (new), `CurrencyRegistryFull` (new).

### 3.3 `deactivate_currency`

**Purpose**: Flip `accepted_currencies[idx].active = false`. The slot is **never removed** so that historical `Contest.entry_fee_by_currency[idx]` and `Contest.entry_fees[idx]` remain valid lookups.

**Auth**: 2-of-3 multisig.

```rust
#[derive(Accounts)]
pub struct DeactivateCurrency<'info> {
    #[account(mut)]
    pub admin: Signer<'info>,
    pub cosigner: Signer<'info>,

    #[account(
        mut,
        seeds = [b"vault"],
        bump = vault_state.bump,
        constraint = vault_state.validate_multisig(&admin.key(), &cosigner.key()) @ VaultError::Unauthorized,
    )]
    pub vault_state: Account<'info, VaultState>,
}
```

**Handler signature**:
```rust
pub fn handle_deactivate_currency(
    ctx: Context<DeactivateCurrency>,
    currency_idx: u8,
) -> Result<()>
```

**Validation**:
1. multisig
2. `(currency_idx as usize) < MAX_CURRENCIES`
3. `accepted_currencies[idx].mint != Pubkey::default()` (slot is in use)
4. `accepted_currencies[idx].active == true` (not already deactivated)

**Side effects**:
- Set `accepted_currencies[idx].active = false`.
- **Note**: this affects FUTURE entries only. Existing open contests with non-zero `entry_fee_by_currency[idx]` will fail entry. Per §11 Q5 decision, `create_contest` also rejects new contests with fees set for deactivated currencies (validation #4 in §3.7).

**CU estimate**: ~5,000.

**Errors**: `Unauthorized`, `InvalidCurrencyIndex` (new), `CurrencyNotActive` (new).

### 3.7 `create_contest`

**Purpose**: Create a new contest with a per-currency entry-fee schedule and a USDC prize pool. The creator pre-funds the USDC prize pool from their ATA into a contest-scoped USDC PDA.

**Auth**: 1-of-3 vault signer as `payer` AND `creator` Phantom signature.

```rust
#[derive(Accounts)]
#[instruction(contest_id: [u8; 32])]
pub struct CreateContest<'info> {
    /// 1-of-3 vault signer — pays SOL rent for Contest PDA + prize-pool PDA
    #[account(mut)]
    pub payer: Signer<'info>,

    /// Creator's Phantom wallet — signs USDC transfer for prize pool
    #[account(mut)]
    pub creator: Signer<'info>,

    #[account(
        seeds = [b"vault"],
        bump = vault_state.bump,
        constraint = vault_state.is_signer(&payer.key()) @ VaultError::Unauthorized,
    )]
    pub vault_state: Account<'info, VaultState>,

    #[account(
        init,
        payer = payer,
        space = 8 + Contest::INIT_SPACE,
        seeds = [b"contest", contest_id.as_ref()],
        bump,
    )]
    pub contest: Account<'info, Contest>,

    /// Per-contest USDC prize pool. PDA at [b"prize_pool", contest_id],
    /// authority = vault_state. Holds the contest's entire prize_pool;
    /// drained on settle_contest or cancel_contest.
    #[account(
        init,
        payer = payer,
        token::mint = payout_mint,
        token::authority = vault_state,
        seeds = [b"prize_pool", contest_id.as_ref()],
        bump,
    )]
    pub prize_pool: Account<'info, TokenAccount>,

    /// Must equal vault_state.payout_mint (canonical USDC).
    #[account(
        constraint = payout_mint.key() == vault_state.payout_mint @ VaultError::InvalidMint,
    )]
    pub payout_mint: Account<'info, Mint>,

    /// Creator's USDC ATA — source of prize pool.
    #[account(
        mut,
        token::mint = payout_mint,
        token::authority = creator,
    )]
    pub creator_token_account: Account<'info, TokenAccount>,

    pub token_program: Program<'info, Token>,
    pub system_program: Program<'info, System>,
    pub rent: Sysvar<'info, Rent>,
}
```

**Handler signature**:
```rust
pub fn handle_create_contest(
    ctx: Context<CreateContest>,
    contest_id: [u8; 32],
    season_id: u32,
    entry_fee_by_currency: [u64; MAX_CURRENCIES],
    max_entries: u32,
    payout_amounts: Vec<u64>,
    prize_pool: u64,
) -> Result<()>
```

**Validation**:
1. `payer` is a vault signer (constraint)
2. checked sum of `payout_amounts == prize_pool` (OPSEC-025 — `try_fold(checked_add)`)
3. `payout_amounts.len() <= 10` (Anchor `max_len`)
4. For each `i < MAX_CURRENCIES`: if `entry_fee_by_currency[i] > 0`, require `vault_state.accepted_currencies[i].mint != Pubkey::default()` AND `vault_state.accepted_currencies[i].active == true` — cannot set a fee for a deactivated or empty slot.
5. At least one `entry_fee_by_currency[i] > 0` OR `prize_pool > 0` (a zero-fee, zero-prize contest is suspicious; flag for review).

**Side effects**:
- Write Contest fields. `status = Open`, `entry_fees = [0; MAX_CURRENCIES]`, `current_entries = 0`.
- If `prize_pool > 0`: SPL Transfer `creator_ata → prize_pool PDA` for `prize_pool` USDC.

**CU estimate**: ~30,000 (Contest PDA init + prize_pool ATA init + 1 SPL CPI).

**Errors**: `Unauthorized`, `InvalidPayoutTiers`, `Overflow`, `InvalidMint`, `InvalidCurrencyIndex`, `CurrencyNotActive`.

### 3.10 `enter_contest`

**Purpose**: Generic single-canonical entry handler. User signs an SPL transfer from their ATA → the chosen currency's operator-revenue ATA. Creates a ContestEntry PDA. Awards seeds. Increments stat counters.

This replaces v0.15.1's `enter_contest_direct` AND the managed `enter_contest`. The single path works for both web3 (Phantom signs) and web2 (server signs with the user's encrypted keypair) — what matters is that the user's keypair signs the transaction.

**Auth**: User signs (controls the source ATA). 1-of-3 vault signer signs as payer (rent + OPSEC-024 routine-op gate).

```rust
#[derive(Accounts)]
#[instruction(entry_num: u32, currency_idx: u8)]
pub struct EnterContest<'info> {
    /// Admin pays rent for the ContestEntry PDA.
    #[account(mut)]
    pub payer: Signer<'info>,

    /// The user's wallet — signs the token transfer.
    #[account(mut)]
    pub user: Signer<'info>,

    /// Per-user stat counter PDA.
    #[account(
        mut,
        seeds = [b"user", user.key().as_ref()],
        bump = user_account.bump,
    )]
    pub user_account: Account<'info, UserAccount>,

    #[account(
        seeds = [b"vault"],
        bump = vault_state.bump,
        constraint = vault_state.is_signer(&payer.key()) @ VaultError::Unauthorized,
    )]
    pub vault_state: Account<'info, VaultState>,

    #[account(
        mut,
        seeds = [b"contest", contest.contest_id.as_ref()],
        bump = contest.bump,
        constraint = contest.status == ContestStatus::Open @ VaultError::ContestNotOpen,
        constraint = contest.current_entries < contest.max_entries @ VaultError::ContestFull,
    )]
    pub contest: Box<Account<'info, Contest>>,

    #[account(
        init,
        payer = payer,
        space = 8 + ContestEntry::INIT_SPACE,
        seeds = [
            b"entry",
            contest.contest_id.as_ref(),
            user.key().as_ref(),
            &entry_num.to_le_bytes(),
        ],
        bump,
    )]
    pub contest_entry: Account<'info, ContestEntry>,

    /// The mint corresponding to `currency_idx`. Validated below.
    pub currency_mint: Box<Account<'info, Mint>>,

    /// User's ATA for the chosen currency.
    #[account(
        mut,
        token::mint = currency_mint,
        token::authority = user,
    )]
    pub user_token_account: Box<Account<'info, TokenAccount>>,

    /// Operator-revenue ATA for the chosen currency.
    /// PDA-seed-bind via `[b"op_rev", currency_mint.key()]`.
    #[account(
        mut,
        seeds = [b"op_rev", currency_mint.key().as_ref()],
        bump,
        token::mint = currency_mint,
    )]
    pub op_rev_ata: Box<Account<'info, TokenAccount>>,

    /// Pinned-season seed schedule (OPSEC-023).
    #[account(
        seeds = [b"season", contest.season_id.to_le_bytes().as_ref()],
        bump = season.bump,
    )]
    pub season: Account<'info, Season>,

    pub token_program: Program<'info, Token>,
    pub system_program: Program<'info, System>,
}
```

**Handler signature**:
```rust
pub fn handle_enter_contest(
    ctx: Context<EnterContest>,
    entry_num: u32,
    currency_idx: u8,
) -> Result<()>
```

**Validation**:
1. `!vault_state.paused`
2. `(currency_idx as usize) < MAX_CURRENCIES`
3. `vault_state.accepted_currencies[currency_idx].active == true`
4. `vault_state.accepted_currencies[currency_idx].mint == currency_mint.key()`
5. `contest.entry_fee_by_currency[currency_idx] > 0` (contest accepts this currency)
6. (constraint) `vault_state.accepted_currencies[currency_idx].op_rev_ata == op_rev_ata.key()` — defense in depth above the PDA-seed bind

**Side effects**:
- SPL Transfer: `user_token_account → op_rev_ata` for `contest.entry_fee_by_currency[currency_idx]`.
- `contest.entry_fees[currency_idx] += entry_fee` (checked).
- `contest.current_entries += 1` (checked).
- `user_account.entries += 1` (checked).
- `user_account.seeds += season.seed_schedule[min(entry_num, 4)]` (checked).
- Initialize `contest_entry` fields including `currency_idx` (decided 2026-05-27, §11 Q2 — store).

**CU estimate**: ~35,000 (PDA init + SPL CPI + 5 deserializations).

**Errors**: `VaultPaused`, `Unauthorized`, `ContestNotOpen`, `ContestFull`, `InvalidCurrencyIndex`, `CurrencyNotActive`, `InvalidMint`, `Overflow`, `EntryFeeNotSet` (new).

### 3.11 `enter_contest_with_token`

**Purpose**: Consume an EntryTokenAccount instead of paying USDC. Otherwise identical to `enter_contest` (PDA-seed-bind on Contest, season pinning, stat-counter increments).

**Auth**: User signs (consents to token consumption). 1-of-3 vault signer signs as payer (rent).

```rust
#[derive(Accounts)]
#[instruction(entry_num: u32)]
pub struct EnterContestWithToken<'info> {
    #[account(mut)]
```

### 3.12 `settle_contest`

**Purpose**: Grade a contest. For each winner, SPL-transfer their payout from the contest's prize_pool USDC PDA → their USDC ATA, set ContestEntry rank/payout/status, increment stat counters.

**Auth**: 2-of-3 multisig.

```rust
#[derive(AnchorSerialize, AnchorDeserialize, Clone)]
pub struct Settlement {
    pub wallet: Pubkey,
    pub entry_num: u32,
    pub rank: u32,
    pub payout: u64,
}

#[derive(Accounts)]
pub struct SettleContest<'info> {
    #[account(mut)]
    pub admin: Signer<'info>,
    pub cosigner: Signer<'info>,

    #[account(
        seeds = [b"vault"],
        bump = vault_state.bump,
        constraint = vault_state.validate_multisig(&admin.key(), &cosigner.key()) @ VaultError::Unauthorized,
    )]
    pub vault_state: Account<'info, VaultState>,

    #[account(
        mut,
        seeds = [b"contest", contest.contest_id.as_ref()],
        bump = contest.bump,
        constraint = (contest.status == ContestStatus::Open || contest.status == ContestStatus::Locked)
            @ VaultError::ContestAlreadySettled,
    )]
    pub contest: Account<'info, Contest>,

    /// Contest's USDC prize pool PDA — source of payouts.
    #[account(
        mut,
        seeds = [b"prize_pool", contest.contest_id.as_ref()],
        bump,
        token::mint = payout_mint,
        token::authority = vault_state,
    )]
    pub prize_pool: Account<'info, TokenAccount>,

    #[account(
        constraint = payout_mint.key() == vault_state.payout_mint @ VaultError::InvalidMint,
    )]
    pub payout_mint: Account<'info, Mint>,

    pub token_program: Program<'info, Token>,

    // remaining_accounts: triples per winner.
    //   [user_account, contest_entry, user_payout_ata]
    // Pattern is identical to v0.15.1 settle_contest, plus the user's USDC ATA
    // as the destination of the SPL transfer.
}
```

**Handler signature**:
```rust
pub fn handle_settle_contest(
    ctx: Context<SettleContest>,
    settlements: Vec<Settlement>,
) -> Result<()>
```

**Validation**:
1. multisig (constraint)
2. `contest.status` is Open or Locked (constraint)
3. payout_mint pinned (constraint)
4. `total_payouts = sum(settlements.payout)` (checked) — `total_payouts <= contest.prize_pool` (NOT `entry_fees + prize_pool` like v0.15.1 — entry fees are operator revenue now, **separate** from the prize pool).
5. No duplicate `(wallet, entry_num)` in the settlements vec.
6. `remaining_accounts.len() == settlements.len() * 3`
7. For each settlement, verify PDA seeds of the 3 remaining-account triples.

**Side effects** (per winner):
- SPL Transfer (PDA-signed by vault_state): `prize_pool → user_payout_ata` for `settlement.payout`.
- ContestEntry: `rank = settlement.rank`, `payout = settlement.payout`, `status = Won if payout > 0 else Lost`. Refuse if status != Active.
- UserAccount: `total_won += payout` (checked), `cashes += (payout > 0 ? 1 : 0)`, `wins += (rank == 1 ? 1 : 0)`.

**Final**: `contest.status = Settled`.

**CU estimate**: base ~25,000 + ~12,000 per winner (one CPI transfer + 3 deserialize-mutate-serialize cycles per pair). 10 winners ≈ 145k CU — well within the 200k default budget but **borderline** at 14+ winners. Recommend Rails batches settlements to ≤ 10 per call OR sets `ComputeBudgetInstruction::set_compute_unit_limit(400_000)`. See §10 (Architectural concerns).

**Errors**: `Unauthorized`, `ContestAlreadySettled`, `SettlementOverflow`, `DuplicateEntry`, `Overflow`, `InvalidMint`.

### 3.16 `close_contest`

**Purpose**: Reclaim SOL rent from a settled or cancelled contest's PDA. Closes the Contest account AND the prize_pool ATA (which must be empty by definition since settle / cancel drained it).

**Auth**: 1-of-3 vault signer.

```rust
#[derive(Accounts)]
pub struct CloseContest<'info> {
    #[account(mut)]
    pub admin: Signer<'info>,

    #[account(
        seeds = [b"vault"],
        bump = vault_state.bump,
        constraint = vault_state.is_signer(&admin.key()) @ VaultError::Unauthorized,
    )]
    pub vault_state: Account<'info, VaultState>,

    #[account(
        mut,
        constraint = contest.status == ContestStatus::Settled || contest.status == ContestStatus::Cancelled
            @ VaultError::ContestNotSettled,
        close = admin,
    )]
    pub contest: Account<'info, Contest>,

    /// Prize pool ATA must be empty before close (settle / cancel drained it).
    /// Closing this here reclaims its ~0.00204 SOL rent.
    #[account(
        mut,
        seeds = [b"prize_pool", contest.contest_id.as_ref()],
        bump,
        token::mint = payout_mint,
        token::authority = vault_state,
        constraint = prize_pool.amount == 0 @ VaultError::PrizePoolNotEmpty,
    )]
    pub prize_pool: Account<'info, TokenAccount>,

    #[account(
        constraint = payout_mint.key() == vault_state.payout_mint @ VaultError::InvalidMint,
    )]
    pub payout_mint: Account<'info, Mint>,

    pub token_program: Program<'info, Token>,
}
```

Note: SPL token accounts can be closed with `close_account` CPI signed by their authority (vault_state). The instruction must do this after the Contest PDA close. See implementation pass.

**CU estimate**: ~15,000.

**Errors**: `Unauthorized`, `ContestNotSettled`, `PrizePoolNotEmpty` (new), `InvalidMint`.

## 7. Test Matrix

### 7.1 Currency registry
- `register_currency` happy path → slot 2 occupied, op_rev ATA created.
- Register a 3rd, 4th, ... up to 16 (MAX_CURRENCIES). 17th rejected with `CurrencyRegistryFull`.
- Re-adding USDC mint at slot N rejected with `CurrencyAlreadyRegistered`.
- Re-adding a previously-deactivated mint rejected with `CurrencyAlreadyRegistered` (preserves currency_idx stability).
- `deactivate_currency` happy path → slot active=false; subsequent `enter_contest` with that idx fails with `CurrencyNotActive`.
- `deactivate_currency` on unused slot → `InvalidCurrencyIndex`.
- `deactivate_currency` on already-deactivated slot → `CurrencyNotActive` (or new `CurrencyAlreadyInactive` if we want a different code — keep DRY, reuse `CurrencyNotActive` for now).
- Wrong cosigner pair on register/deactivate → `Unauthorized`.

### 7.2 Contest lifecycle
- Open → Locked → Open (lock then unlock): both pass.
- Open → Locked → Settled: settle from Locked succeeds.
- Open → Settled (no intermediate lock): succeeds.
- Open → Cancelled: succeeds, prize pool refunds to creator.
- Locked → Cancelled: succeeds.
- Settled → Cancelled: rejected with `ContestNotCancellable`.
- Cancelled → anything: rejected.
- `lock_contest` on already-Locked: `ContestNotOpen`.
- `unlock_contest` on Open: `ContestNotLocked`.

### 7.3 enter_contest
- Web3 path (user with USDC ATA) — happy path.
- Web2 path (Rails-held keypair signs the same way) — happy path; assert identical on-chain behavior.
- Enter while paused → `VaultPaused`.
- Enter on Locked → `ContestNotOpen`.
- Enter on full contest → `ContestFull`.
- Enter with `currency_idx` = 17 → `InvalidCurrencyIndex`.
- Enter with a deactivated currency → `CurrencyNotActive`.
- Enter with `currency_mint.key() != accepted_currencies[idx].mint` → `InvalidMint`.
- Enter with a contest that has `entry_fee_by_currency[idx] == 0` → `EntryFeeNotSet`.
- Insufficient ATA balance → SPL transfer fails (no custom error needed — SPL surfaces InsufficientFunds).
- `wallet` not a vault signer in payer position → `Unauthorized`.
- Stat counters: confirm `entries++` and `seeds += schedule[idx]` after a successful entry.

### 7.4 enter_contest_with_token
- Happy path.
- Wrong-owner token → `EntryTokenWrongOwner`.
- Already-consumed token → `EntryTokenAlreadyConsumed`.
- Same as above but contest is Locked / full / paused.

### 7.5 settle_contest
- Settle with 1 winner, 5 winners, 10 winners → all succeed (CU within 200k).
- Settle with 14 winners (CU budget bump required) → succeeds with `set_compute_unit_limit(400_000)`.
- Settle with 20 winners → confirm whether single TX or batch required (architectural concern §10).
- Payout sum > prize_pool → `SettlementOverflow`.
- Duplicate `(wallet, entry_num)` → `DuplicateEntry`.
- Same wallet, different entry_num → both processed.
- Settle entry already at status=Won (replay attempt) → `ContestAlreadySettled` per-entry.
- Wrong cosigner pair → `Unauthorized`.
- After settle: confirm `cashes++` for any rank>0 / payout>0, `wins++` only for rank==1, `total_won += payout`.
- Confirm `prize_pool` ATA empty after a full-pool settle.

### 7.6 cancel_contest
- Cancel on Open: refunds full prize_pool to creator ATA.
- Cancel on Locked: same.
- Cancel after partial settle (i.e. some entries settled, status was still Open somehow): N/A — settle flips status to Settled atomically. Confirm.
- Cancel on Settled / Cancelled: `ContestNotCancellable`.
- Cancel where prize_pool ATA balance differs from `contest.prize_pool` (defense in depth): instruction sweeps the on-chain balance, not the stored field.
- Wrong creator_token_account (different wallet) → constraint rejects (`token::authority = contest.creator`).

### 7.7 sweep_operator_revenue
- Sweep happy path: drain op_rev ATA → treasury ATA.
- Sweep with `amount > op_rev_ata.amount` → `InsufficientBalance`.
- Sweep with `amount == 0` → drains all.
- Sweep on empty ATA → `EmptyRevenueAccount`.
- Wrong cosigner pair → `Unauthorized`.
- `treasury_ata.owner != vault_state.treasury_authority` → reject with `TreasuryAuthorityMismatch` (decided 2026-05-27, §11 Q3).

### 7.8 create_contest
- Happy path (1 currency: USDC at $5).
- Multi-currency: USDC=$5, USDT=$5 — both slots set.
- Mixed: USDC=$5, USDT=0, EURC=$5 — only the non-zero slots are "accepted".
- Fee set for unused currency slot (slot empty) → reject with `InvalidCurrencyIndex`.
- Fee set for deactivated currency → reject with `CurrencyNotActive`.
- Payout sum ≠ prize_pool → `InvalidPayoutTiers`.
- Creator's ATA has insufficient USDC → SPL transfer fails.
- All-zero fees + zero prize pool: per §3.7 validation 5, reject with a custom error or treat as a valid "showcase" contest? Mark for Alex review — current spec rejects.

### 7.9 Multisig / pause / ICF observations
- All 2-of-3 instructions reject `admin == cosigner`.
- All 2-of-3 instructions reject non-signer cosigner.
- Pause / unpause + paused enter_contest: same coverage as v0.15.1.
- After v0.15.1 ICF observations (the 4 entry handlers shared several KB via closure-folding): v0.16 collapses them to 2 (`enter_contest`, `enter_contest_with_token`), so we expect SLIGHTLY less ICF benefit per handler but ~half the validator-overhead total. Confirm with a post-build `llvm-objdump --syms | rustfilt` pass.

## 8. Byte Budget

### 8.1 v0.15.1 baseline

Per `/Users/alex/projects/turf-vault-deploy-cost.html`:
- Total ELF: **466,576 bytes** (~456 KB).
- `.text`: 396,336 (85% of binary).
- Section attribution: 16 handlers (16 × try_accounts validators + 16 × handle_* functions) ≈ 163,384 bytes. Rest is Anchor runtime, Rust core/alloc, IDL embed, syscalls.
- Permanent rent: (466,576 + 128) × 6960 = **3.247 SOL** (ProgramData + Buffer = 6.496 SOL float during deploy).

### 8.2 v0.16 projected

Adds:
- `register_currency` (~8 KB est. — small validator, small handler)
- `deactivate_currency` (~3 KB)
- `lock_contest` (~2 KB — tiny)
- `unlock_contest` (~3 KB — slightly larger due to 2-of-3 validator)
- `cancel_contest` (~12 KB — SPL CPI with PDA signer)
- `sweep_operator_revenue` (~10 KB — SPL CPI with PDA signer)

Drops (from v0.15.1 byte-attribution table):
- `deposit`: -9,632 bytes
- `withdraw`: -10,048 bytes (but settle_contest's logic was ~10,048 — those byte counts seem swapped in the source data; either way, deposit + withdraw together are ~20 KB)
- `enter_contest` (managed, balance-debit): -15,128 bytes
- `enter_contest_with_token` (managed): -15,352 bytes (split: -15,944 if we include the bigger of the two by the table)
- Daily-cap fields (`DAILY_WITHDRAW_CAP`, `DAILY_WINDOW_SECONDS`) and their inline code in withdraw: a few KB savings rolled into the withdraw drop.

Modifies:
- `initialize`: bigger (more accounts init — 2 ATAs at init time instead of 2 vault token PDAs; broadly comparable). Possibly +2-3 KB.
- `create_contest`: bigger (new prize_pool ATA init + per-currency loop). ~+5 KB.
- `enter_contest`: replaces enter_contest_direct, similar size. ~17,784 bytes (unchanged).
- `settle_contest`: bigger (now does an SPL CPI per winner). ~+5 KB.
- State serializers: `VaultState` grew (1480 bytes vs ~205 today) but borsh layout cost grows roughly linearly — call it +6 KB.

**Rough projection**:
- Drops: -50 KB (deposit, withdraw, 2 managed entry variants).
- Adds: +38 KB (6 new instructions, average ~6 KB each).
- Modifications: +18 KB (initialize, create_contest, settle, state grew).
- **Net**: roughly **+6 KB** vs. v0.15.1. Final binary: ~470 KB. **Slightly bigger**, not smaller.

This is a wash on rent terms — the savings from dropping deposit/withdraw are eaten by the per-currency surface area. The win is operational, not byte-economic:

- 6+ Heroku endpoints to write that today are handled by Rails are subsumed by Solana txs.
- No more pooled-balance reconciliation between Rails and the chain.
- USDT (and future EURC, etc.) work without redeploying.
- Operator revenue is on-chain and auditable.

If Alex wants the binary smaller for cost reasons, the levers (in order of pain):

1. Drop pause/unpause (-3,152 bytes). Trades emergency response for binary size.
2. Drop close_contest (-3,424). Leaves rent locked on settled contests.
3. Drop `enter_contest_with_token` (-15+ KB). Forces all entries to be paid in USDC — breaks the free-entries product.
4. Use `no-idl` feature (-26,592). Forces external IDL distribution; no more `anchor idl fetch`.
5. Switch to a hand-rolled accounts layout (massive refactor, -30+ KB potential).

Recommend NONE of these for the first mainnet deploy. Ship the ~470 KB binary; revisit after launch with real cost telemetry.

### 8.3 Permanent rent projection

- ProgramData: (470,000 + 128) × 6960 ≈ 3.27 SOL (rises ~0.02 SOL vs v0.15.1).
- VaultState PDA: 0.0112 SOL.
- Per-currency op_rev ATA: 0.00204 SOL × 16 max = 0.0326 SOL (but you only pay for what's registered — start with 2 = 0.00408 SOL).

**Pre-deploy total**: ~3.29 SOL permanent (program + initial state). Float during deploy: ~6.6 SOL.

## 10. Architectural Concerns (Found While Writing)

### 10.1 settle_contest CU budget at 10+ winners

v0.15.1's settle is roughly 5k CU base + 3k per pair. v0.16 adds an SPL CPI per pair (~3k more CU each), so the per-pair cost roughly doubles to ~6-7k. Rough new budget:

- 5 winners: 5k + 5 × 7k = 40k CU. Fine.
- 10 winners: 5k + 10 × 7k = 75k CU. Fine.
- 20 winners: 5k + 20 × 7k = 145k CU. Within the 200k default.
- 30 winners: 5k + 30 × 7k = 215k CU. **Over default**, needs `set_compute_unit_limit`.
- 50 winners: 360k CU. Needs `set_compute_unit_limit(400_000)`, plus heap usage may bite.

Actions:
- Rails should always set `ComputeBudgetInstruction::set_compute_unit_limit(400_000)` for settle (cheap insurance).
- Rails should batch settlements into multiple calls when winner count > 25. settle_contest is idempotent per-entry (each ContestEntry transitions Active → Won/Lost once), so a contest can be settled across multiple TXs IF the final TX flips status to Settled. This is a flow change — current `handle_settle_contest` flips status unconditionally. Spec change needed: add an `is_final: bool` parameter, set status=Settled only when `is_final == true`.
- **Decided 2026-05-27 (§11 Q7)**: single-call only; Rails sets `set_compute_unit_limit(400_000)` on every settle TX. Caps max winners at ~50. Multi-call pattern deferred until needed.

### 10.2 MAX_CURRENCIES = 16 and account-list TX size

Solana txs cap at 1232 bytes (legacy) / 1644 with v0 versioned txs. The `enter_contest` instruction passes ~12 accounts at runtime — well under any limit. **But**:

- `register_currency` over many slots: each call passes 7 accounts. Fine.
- The 1280-byte `accepted_currencies` array does NOT pass into every TX as remaining_accounts — it lives in VaultState, which is loaded once. **Not** a TX-size concern.
- Compute-unit cost of iterating 16 slots in `create_contest` validation: 16 × ~50 CU = 800 CU. Negligible.

`MAX_CURRENCIES = 16` is comfortable. Drop to 8 if Alex wants a smaller VaultState (saves 640 bytes / ~0.0045 SOL of permanent rent).

### 10.3 currency_idx stability under deactivate-then-reactivate

`deactivate_currency` sets `active = false` but preserves the slot. **If we ever add a `reactivate_currency`**, slots become re-active. The spec deliberately does NOT include reactivate — once deactivated, a currency stays inactive for the life of the program (or until full re-init via a new mainnet program ID).

Reason: if USDC@idx0 is deactivated and then re-activated later, contests created during the deactivation window with `entry_fee_by_currency[0] > 0` would suddenly become enterable again — surprising behavior. Cleaner to never re-activate; if you need to bring back a currency, register it in a new slot.

### 10.4 Prize pool ATA close requires it to be empty

A 1-USDC-rounding-error in payouts could leave the prize_pool ATA with 0.000001 USDC after settle, blocking close_contest with `PrizePoolNotEmpty`. Mitigation:

- Rails should always validate `sum(payouts) == prize_pool` before submitting settle. settle's own validation does `<= prize_pool`, not `==`, so dust is possible.
- Options:
  - (a) Tighten `settle_contest` to require `==`. Risk: a graceful "rake" model where 1% of prize_pool stays in the pool isn't possible.
  - (b) Add a `sweep_dust` instruction that transfers any residual prize_pool USDC to operator-revenue. Adds bytes; messy.
  - (c) Allow `close_contest` to also do a final sweep of any leftover USDC to op_rev_ata. **Recommend this** — small code add, clean.

**Decided 2026-05-27 (§11 Q8)**: option (c) — `close_contest` sweeps any residual prize_pool USDC to operator-revenue USDC ATA before closing the prize_pool ATA. Removes the `PrizePoolNotEmpty` failure mode.

### 10.5 Squads upgrade authority + first-deploy

The first mainnet deploy will use `solana program deploy` from Alex Bot's keypair, then `set-upgrade-authority` to the Squads vault PDA. Verify the Squads vault PDA is correctly derived BEFORE running set-upgrade-authority — once you hand authority over, only the Squad can take it back.

Test on devnet against a throwaway Squads vault first.

### 10.6 token_2022 footprint

v0.15.1's `.text` includes ~44 KB for "Solana + SPL syscalls" (including unused `spl_token_2022` + `spl_associated_token` instruction builders pulled in by Anchor 0.32.1 unconditionally — see `feedback_anchor_spl_token_2022_required.md`). v0.16 does NOT change Anchor version, so this stays. If we ever upgrade to Anchor 0.33+ and they fix the conditional include, we get ~20 KB free.

## 11. Decisions (resolved 2026-05-27)

### Q1. cancel_contest refund-to-entrants policy — DECIDED: no on-chain refund
`cancel_contest` refunds only the prize_pool to creator and flips status to Cancelled. Entry fees stay in operator-revenue (already collected, treated as platform revenue).

**Operator playbook for cancelled contests**: reduce the announced prize-pool refund obligation by minting free-entry tokens to affected entrants via `mint_entry_token` (existing instruction). Each affected user gets a goodwill credit usable on a future contest. This is a Rails-side workflow, not a contract feature — keeps `cancel_contest` minimal and gives operations flexibility in how generously to compensate.

### Q2. ContestEntry.currency_idx — DECIDED: store
1-byte field. Stored as `u8` on every ContestEntry. Sentinel `u8::MAX` for token-funded entries (no SPL currency). Decoded as "currency name" via VaultState.accepted_currencies[idx] in the UI.

### Q3. Treasury wallet for sweep_operator_revenue — DECIDED: Squads vault PDA
Pin `treasury_authority: Pubkey` in VaultState (32 bytes in `_reserved`), set at `initialize` time to the Squads vault PDA `BW13kgfiG2koFn3WRkte21NW9TFygsD1ge2fNJdjH6kC` (same vault that holds the program upgrade authority). `sweep_operator_revenue` constrains `treasury_ata.owner == vault_state.treasury_authority`. Rotation deferred — would need a future `update_treasury_authority` (2-of-3) instruction.

Reasoning: no new trust domain to manage. The same 2-of-3 multisig that approves contract upgrades approves treasury spend. A leaked Alex Bot key alone cannot drain swept revenue.

### Q4. Expose entry-fee tally per contest — DECIDED: yes (UI only, no contract change)
`Contest.entry_fees: [u64; 16]` is updated on every paid entry; standard `getAccountInfo` + borsh decode. Rails decoder updates for new Contest layout; UI renders the per-currency tally on the contest detail page. No contract change needed.

### Q5. deactivate_currency forbid new contests using the currency — DECIDED: yes
`create_contest` validation #4 (per §3.7) rejects any `entry_fee_by_currency[idx] > 0` where `vault_state.accepted_currencies[idx].active == false`. Existing open contests with that currency continue to honor entries until their natural lifecycle ends. No re-activation supported — if a currency needs to come back, register it in a new slot.

### Q6. Always-zero-fee contests — DECIDED: reject
`create_contest` validation #5 rejects any contest where ALL `entry_fee_by_currency` slots are zero AND `prize_pool == 0`. Every contest must have either a fee or a prize. Pure leaderboard/seed-farming contests are out of scope; if needed later, will require a separate `create_promo_contest` instruction with explicit operator authorization.

### Q7. Incremental settle (see §10.1) — DECIDED: defer
Option (c) — single-call settle with explicit `set_compute_unit_limit(400_000)` set by Rails. Caps max winners at ~50. If a contest ever needs more, revisit with the `is_final: bool` multi-call pattern. Rails is responsible for setting the CU limit on every settle TX.

### Q8. close_contest dust handling (see §10.4) — DECIDED: sweep to operator revenue
Option (c) — `close_contest` performs a final SPL transfer of any residual prize_pool USDC to the operator-revenue USDC ATA before closing the prize_pool ATA. Removes the `PrizePoolNotEmpty` failure mode and gives operations the "rake" path if needed (a contest can be intentionally over-funded to accumulate a margin). Spec §3.16 updated accordingly.
